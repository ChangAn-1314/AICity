# AICity 无录屏项目演示视频设计

日期：2026-03-10

## 1. 设计目标

为 `demo-video` 设计一支不依赖真实录屏的项目演示视频，用于比赛答辩场景，整体风格要求专业、大气、流畅，并在 `75-90 秒` 内完整讲清 AICity 的核心能力闭环。

本次设计已确认的约束如下：

- 用途：比赛答辩版
- 时长：`75-90 秒`
- 素材策略：不使用连续录屏
- 呈现路线：选择“界面重构动画”，即用 Remotion 重新编排关键产品界面与信息模块，而非播放真实前端操作

## 2. 方案取舍结论

本次最终采用“界面重构动画”而不是“录屏演示”或“纯概念宣传片”。原因如下：

- 比起录屏，界面重构动画更容易保证镜头节奏、信息密度和整体质感
- 比起纯概念片，界面重构动画仍然保留真实产品结构，能让评委感知项目确实具备可展示的功能链路
- 当前仓库已具备 `demo-video` Remotion 工程和 `AICityFornt` 的完整功能模块，适合提取视觉结构和业务逻辑后重新编排为视频场景

因此，本片的定位不是“录屏包装”，而是“一支发布会级别的产品演示片”。

## 3. 视觉方向

整体视觉建议升级为“深色指挥中心”风格，而非继续沿用强霓虹赛博朋克路线。

- 主色：深蓝黑、石墨灰、钛银
- 强调色：冷青色用于信息流、警示橙用于风险与预警
- 动效策略：少量大位移镜头，重点信息用局部放大、脉冲、数字跃迁和连线跟踪完成表达
- 质感策略：背景持续微动，前景模块层次清晰，避免廉价的满屏发光和无意义粒子堆叠

目标感受是：政企可信、技术先进、节奏利落。

## 4. 叙事结构

整片控制在 `82 秒`，采用 `8 段式` 结构：

| 段落 | 时长 | 目标 |
| --- | --- | --- |
| 开场定调 | 8s | 建立项目定位与城市态势空间 |
| 全域态势监测 | 10s | 展示 3D 地图与热点全局感知 |
| 多源舆情识别 | 12s | 展示来源、情感、关键词、热度等结构化分析 |
| AI 场景还原 | 12s | 将热点点位转为简化三维现场 |
| 趋势预测 | 10s | 展示风险变化、扩散曲线与未来趋势 |
| 决策模拟 | 12s | 展示多个响应方案及效果对比 |
| 报告生成 | 8s | 展示从研判到报告交付的闭环 |
| 结尾收束 | 10s | 汇总能力，完成答辩式品牌落点 |

对应的帧规划为：

- `opening`：`0-239`
- `monitoring`：`240-539`
- `analysis`：`540-899`
- `reconstruction`：`900-1259`
- `prediction`：`1260-1559`
- `simulation`：`1560-1919`
- `report`：`1920-2159`
- `outro`：`2160-2459`

总帧数 `2460`，按 `30fps` 输出为 `82 秒`。

## 5. 每段分镜说明

### 5.1 开场定调

从黑场切入一句核心主张，例如“城市舆情，不止监测，更要预判与推演”。随后城市网格、风险脉冲和关键节点自远及近建立。镜头最终收束到主舞台，为后续能力展示做空间预热。

### 5.2 全域态势监测

以 3D 城市地图为主视觉，叠加热点建筑发光、区域风险圈、新闻滚动卡和城市选择条，强调“全域接入、实时感知、重点定位”。该段负责回答“哪里出事了”。

### 5.3 多源舆情识别

将事件详情卡、来源标签、情感比重、关键词云、热度条和分析结论模块化排列，通过卡片翻转、数字跃迁和信息聚合表现“从海量信息到结构化认知”。该段负责回答“到底发生了什么”。

### 5.4 AI 场景还原

从热点点位直接拉出一段简化三维现场，使用仓库已有 `glb` 资源构造行人、车辆或事件载体，表现“舆情理解不仅停留在文本层，而是能还原现场态势”。

### 5.5 趋势预测

将趋势曲线、扩散路径、风险指数卡和预测标签整合为未来态视图，颜色从冷青逐步转向警示橙，表达“系统具备预判而非只做复盘”的能力。

### 5.6 决策模拟

在画面中央放置 `2-3` 个决策方案卡，分别展示响应速度、风险回落、影响范围和推荐等级，通过对比强化“系统不仅给建议，还能做多方案推演”。

### 5.7 报告生成

前面产生的关键模块自动汇入一张结构完整的研判报告页，并通过页签切换、摘要聚焦和完成态标签表现“从监测、分析、推演到交付”的业务闭环。

### 5.8 结尾收束

所有能力模块回收至统一总控界面，最后落到完整项目名与一句结论型话术，结束方式要稳、准、干净，避免花哨收尾。

## 6. 实现架构

不建议继续沿用当前 `demo-video/src/SceneV2.tsx` 的单体式设计，而应改造成“分场景组件 + 统一脚本数据 + 共享视觉组件”的结构。

建议目录结构如下：

- `demo-video/src/compositions/ProductDemo82.tsx`
- `demo-video/src/data/video-script.ts`
- `demo-video/src/theme/tokens.ts`
- `demo-video/src/theme/fonts.ts`
- `demo-video/src/scenes/*.tsx`
- `demo-video/src/components/shared/*.tsx`
- `demo-video/src/lib/timing.ts`

结构原则如下：

- `Root.tsx` 只负责注册主 Composition
- 主 Composition 负责按帧调度各个场景
- 场景组件只关心当前段落的视觉表达
- 文案、数值、段落时长统一由脚本数据驱动
- 共享卡片、标题、数字、脉冲、曲线组件统一复用，避免每段重新造 UI

## 7. 技术策略

采用 `2D 主导 + 轻 3D 点缀` 的方式实现。

- 2D 部分：标题、卡片、数字、图表、报告页、方案对比等，使用 Remotion + React DOM 实现，便于精细排版和快速改文案
- 3D 部分：城市空间建立镜头、热点脉冲、简化现场还原、少量空间感粒子，使用 `@remotion/three`、React Three Fiber 与现有 `glb` 资源实现

这样可以兼顾三点：

- 保证整体流畅度
- 控制后期修改成本
- 避免把所有内容压到 Three.js 中导致调试和渲染成本过高

## 8. 数据流设计

视频的所有内容都由一份静态脚本驱动，而不是直接复用前端实时状态。

脚本数据建议包含：

- 场景顺序与时长
- 中文标题、副标题、结尾文案
- 城市名、事件名、风险标签、关键词
- 关键指标数值
- 决策方案及比较结果
- 报告摘要段落

好处如下：

- 渲染结果稳定可复现
- 改文案、数字、案例名时无需改动场景逻辑
- 后续若改成 `60 秒` 或 `90 秒` 版本，只需调整脚本和时长分配

## 9. 资源策略

优先复用现有仓库资源，但不直接嵌入 Vue 页面。

可直接参考或复用的来源如下：

- `demo-video/src/Root.tsx`：Composition 入口保留
- `demo-video/src/SceneV2.tsx`：保留其“高质量视频包装”思路，但重构成分段编排
- `AICityFornt/src/components/features/`：提取信息结构与视觉语言
- `AICityFornt/public/models/*.glb`：用于 AI 场景还原段落

建议新增本地字体与统一视觉 token，避免继续使用当前示例代码中的系统字体堆栈。

## 10. 容错与降级策略

需要预先接受这是一支“可控演示片”，因此应设计明确的降级路线：

- 某个 `glb` 模型过重或加载失败时，退化为简单几何体、轮廓线和光晕效果
- 某些高开销粒子、阴影、景深效果若影响渲染，优先保留主叙事与关键信息，减少装饰效果
- 若后续时长压缩，优先减少空镜和缓冲段，不削弱“监测 -> 分析 -> 预测 -> 决策 -> 报告”的核心闭环

## 11. 验证方式

本项目的正确性主要依赖“视觉检查 + 渲染验证”，而不是复杂的业务逻辑测试。

建议的验证顺序：

1. 在 Remotion Studio 中逐段预览节奏
2. 输出关键帧静帧检查画面质量
3. 先渲染低成本预览版，确认节奏和转场
4. 最后渲染 `1920x1080 / 30fps` 正式版

代码层面只对脚本结构、时长计算、帧区间映射等纯函数做轻量测试。

## 12. 设计结论

本设计的核心不是“替代录屏”，而是把 AICity 的功能闭环重新组织成一支更适合比赛答辩的专业产品演示片。它既保留真实项目结构，又通过 Remotion 的镜头和动效体系放大表达力。最终目标是让评委在 `82 秒` 内明确感知：这个项目能看、能懂、能推演、能交付。
