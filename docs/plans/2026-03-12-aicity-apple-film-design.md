# AICity 苹果风产品宣传片设计

日期：2026-03-12

## 1. 设计目标

为 `demo-video2` 设计并落地一支用于项目展示与答辩的产品介绍宣传片，整体气质参考苹果发布会短片：克制、大气、精致、留白充足、动效顺滑。

本次已经确认的约束如下：

- 输出目录：`demo-video2/`
- 形式：Remotion 工程化宣传片，而不是录屏包装
- 风格：苹果风，高级、冷静、精密，不做赛博朋克霓虹堆叠
- 用途：产品介绍宣传片
- 音频策略：`无旁白`，以音乐节奏、镜头运动和大字标题推进叙事
- 内容策略：既要保留 AICity 的真实产品能力闭环，也要避免普通大屏宣传片的廉价感

## 2. 方案取舍结论

本次采用“苹果发布会式产品叙事”为主，“城市态势与决策系统语义”为辅的混合方案。

- 不采用“纯录屏”方案，因为它很难获得高级质感，镜头节奏也受真实操作限制
- 不采用“纯概念片”方案，因为它会削弱产品可信度和功能闭环表达
- 最终选择“产品为主角”的宣传片表达：AICity 本身像一件被发布、被展示、被拆解说明的精密产品，城市态势、风险演化、决策模拟等能力作为它被优雅展开的功能层

因此，本片定位是：`一支苹果风的政企 AI 产品宣传片`，而不是普通城市治理大屏 demo。

## 3. 视觉方向

### 3.1 基础气质

- 主背景：黑钛、深石墨、冷灰渐变
- 主要强调色：冰蓝、银白、少量冷青
- 次级提示色：仅在风险与预警段落少量引入琥珀橙
- 光效策略：边缘高光、玻璃质感、柔和发光、低频呼吸，而不是满屏粒子或强霓虹描边

目标观感是：像苹果在发布一款城市级智能决策产品，而不是在播一套炫技模板。

### 3.2 版式原则

- 大标题使用超大字号与高留白，句子短、判断感强
- 产品画面以“悬浮屏幕”“整洁卡片”“精密线框”方式呈现
- 每一屏只表达一个重点，避免信息同时爆炸
- 动效宁可少，也必须稳：推进、漂移、淡入、局部放大优先，避免花哨翻转和无意义弹跳

### 3.3 字体策略

为了维持苹果风精致感，字体必须单独管理，不能直接依赖系统默认栈。

- 采用 `Remotion fonts` 方案统一加载字体
- 标题与数字采用偏几何、现代、克制的无衬线字重体系
- 在实现中增加文本测量和自适应缩放兜底，确保中文大标题不溢出、不挤压

## 4. 叙事结构

整片建议控制在 `72-80 秒`，默认版本定为 `76 秒 / 2280 帧 / 30fps`。

采用 `7 段式` 结构：

| 段落 | 时长 | 目标 |
| --- | --- | --- |
| 开场定调 | 8s | 用一句大字建立“监测只是起点，决策才是终点”的认知 |
| 产品登场 | 10s | 让 AICity 主界面像发布会主角一样进入画面 |
| 多源识别 | 12s | 展示情绪、关键词、来源聚合，回答“发生了什么” |
| 全域监测 | 12s | 展示城市地图、风险热点、全局态势，回答“发生在哪里” |
| 趋势预测 | 12s | 展示风险曲线、扩散路径和预测判断，回答“接下来会怎样” |
| 决策与报告 | 12s | 展示多方案模拟、回落效果和报告生成，回答“应该怎么做” |
| 结尾收束 | 10s | 模块归一到总控画面，完成品牌收束 |

## 5. 分镜说明

### 5.1 开场定调

纯黑钛背景中，一句大字缓慢显现，例如：

`看见城市情绪，只是第一步。`

下层是一道非常细的冷白高光横线和微弱空间雾感，暗示“系统即将启动”。这段必须克制，目标是建立高级感，而不是急着展示功能。

### 5.2 产品登场

AICity 主界面以悬浮玻璃屏形式从远处推进，轻微倾斜后回归正视角。标题、副标题、产品名依次出现，形成典型发布会产品 reveal。界面素材优先参考 `docs/source/UI/` 和现有前端的视觉结构，但不直接嵌入真实页面。

### 5.3 多源识别

界面被拆成多个信息模块：事件卡、来源标签、情绪占比、关键词与核心结论。镜头做局部推进与模块重组，强调系统能把海量舆情压缩成结构化判断。

### 5.4 全域监测

切入全国到城市的态势地图语言，热点脉冲、区域风险环、关键点位说明卡顺序出现。此处保留“城市治理”语义，但视觉上仍然是苹果风的冷静展示，而不是大屏风格全开。

### 5.5 趋势预测

风险指数曲线、扩散路径、预测结论卡在同一空间内逐层浮现。颜色从冷白/冰蓝渐进到少量琥珀橙，表达系统从“理解现在”进入“预判未来”。

### 5.6 决策与报告

画面中间放出 `2-3` 个处置方案卡，比较响应速度、风险回落、影响范围和推荐等级。随后这些结构自动汇入一页完整的研判报告，表现“从感知到推演再到交付”的闭环。

### 5.7 结尾收束

所有能力模块退回主界面总控视图，只保留产品名与一句结论型文案，例如：

`AICity，让城市风险更早被看见，更稳被决策。`

收尾必须干净，不使用花哨爆闪或大面积粒子散场。

## 6. Remotion 高级用法结论

本设计已结合 `remotion-best-practices` 中与本项目强相关的规则，确定以下落地原则：

### 6.1 Composition 与参数化

- `Root.tsx` 只负责注册 composition
- 主 composition 使用 `defaultProps` 和 `schema` 参数化，便于切换文案、品牌名、时长版本
- 预留 `calculateMetadata`，用于计算总时长、默认输出名以及后续短版/长版衍生

### 6.2 Sequence 与转场

- 场景级编排以 `Sequence` 或 `TransitionSeries` 为核心，而不是单文件硬堆帧判断
- 所有关键 Sequence 默认增加 `premountFor`，避免首帧加载抖动
- 转场以极短 `fade` 与轻量 `slide` 为主，确保精致感
- 明确考虑 `TransitionSeries` 会缩短总时长，统一由时间工具函数计算总帧数

### 6.3 时间与动效

- 标题和大组件入场优先使用 `spring({config: {damping: 200}})`，得到无明显回弹的自然运动
- 精细位置、透明度、缩放使用 `interpolate()` 与 `Easing.bezier()` 控制
- 不做无意义持续抖动或过度 bounce

### 6.4 字体与文本测量

- 字体先加载，再进入文本测量逻辑
- 对超大中文标题使用 `fitText()` 与文本溢出检查
- 文字测量使用与渲染一致的字重、字距与字号，避免导出时排版偏差

### 6.5 资源与媒体

- 图片必须使用 `<Img>`
- 视频必须使用 `@remotion/media` 的 `<Video>`
- 音频必须使用 `@remotion/media` 的 `<Audio>`
- 本地资源统一复制到 `demo-video2/public/` 后通过 `staticFile()` 引用

### 6.6 3D 使用原则

- 仅在必要处使用 `@remotion/three` 增加空间感，例如短暂的城市空间镜头或现场还原镜头
- 所有 3D 动画必须由 `useCurrentFrame()` 驱动
- 禁止使用 `useFrame()` 产生自运行动画，避免渲染闪烁
- `ThreeCanvas` 内若使用 `Sequence`，必须设置 `layout="none"`

### 6.7 Overlay 与光漏特效

- 如需增强镜头呼吸感，可在个别切点加入极轻量 `LightLeak` overlay
- 光漏只作为辅助，不得成为主风格

## 7. 工程架构

建议目录结构如下：

- `demo-video2/package.json`
- `demo-video2/tsconfig.json`
- `demo-video2/remotion.config.ts`
- `demo-video2/vitest.config.ts`
- `demo-video2/public/`
- `demo-video2/src/index.ts`
- `demo-video2/src/Root.tsx`
- `demo-video2/src/compositions/AICityAppleFilm.tsx`
- `demo-video2/src/data/film-script.ts`
- `demo-video2/src/lib/timing.ts`
- `demo-video2/src/lib/metadata.ts`
- `demo-video2/src/theme/tokens.ts`
- `demo-video2/src/theme/fonts.ts`
- `demo-video2/src/components/shared/*.tsx`
- `demo-video2/src/scenes/*.tsx`
- `demo-video2/src/lib/__tests__/*.test.ts`

结构原则：

- `Root.tsx` 只做注册
- 主 composition 负责总时长、转场和场景拼装
- 场景组件只关心当前段落视觉表达
- 所有标题、数字、时长和主文案由脚本数据驱动
- 可复用视觉组件沉入 `shared`

## 9. 验证方式

本项目以“轻测试 + 强视觉验证”为主。

- 对纯函数做单元测试：脚本结构、总帧数、转场扣减、metadata 计算
- 在 Studio 中逐段检查节奏
- 渲染关键静帧检查版式、文字、图层、边缘发光与色彩平衡
- 最后渲染 `1920x1080 / 30fps` 正式版

## 10. 设计结论

这支片子的核心不是“把已有页面做成视频”，而是把 AICity 重新包装成一件值得被发布的产品。通过苹果式的镜头组织、极简但精确的排版、克制而顺滑的 Remotion 动效、以及对城市决策闭环的清晰表达，这支 `demo-video2` 最终应当呈现出：`既像产品发布片，又能让人看懂它确实能解决什么问题。`
